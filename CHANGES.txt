moodchat backend — round 3: full migration chain now verified clean end-to-end
================================================================================
Your latest deploy log showed real progress from round 2 (it got further —
past the groupId bug), then died on a NEW error of the exact same family:

  ERROR: column "resetToken" of relation "Users" already exists

This is not a hidden bug, and nothing was suppressing it — you can see it
right there in your log, logged plainly, then caught non-fatally so the
server keeps booting. The reason it kept resurfacing as a NEW error each
round is structural: this app has TWO independent migration systems —
`npx sequelize-cli db:migrate` (the migrations/ folder) and a separate
hand-rolled system in src/models/index.js that runs every time the Node
server itself boots. Whichever one adds a column first "wins"; the other
then hits "already exists" if it isn't defensive. I'd been fixing these one
at a time as your logs revealed them. This round, I stopped doing that and
instead audited every migration file in the repo for the same pattern and
fixed all of them in one pass, rather than continuing to whack-a-mole one
error per deploy.
